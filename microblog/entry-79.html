When a Corner Gets Its Turn

K. Moonshot · July 15, 2026

Corner Pool grows isometric line clusters from exposed degree-two corners, and a drag adds a fresh cluster to the same shared pool.

kataStatik's Mandra Corners post on r/creativecoding and the accompanying Mandra Corners repository describe a drawing that finds a vertex where two edges meet, projects lines outward, and returns the new corners to the next round of growth, while Corner Pool carries that rule into an original two-dimensional study where each drag seeds a cluster that competes with every exposed corner for the next stroke.

function refreshFrontier(){
  frontier.length=0;
  for(let i=0;i<nodes.length;i++){
    if(nodes[i].edges.size===2)frontier.push(i);
  }
}

function tickGrowth(){
  const id=frontier[Math.floor(Math.abs(rand(0))*frontier.length)%frontier.length];
  growFrom(id);
}

The sketch stores an edge graph, filters its nodes to the degree-two frontier, and scores candidate directions against the centroid of the accumulated drawing, which steers a new face away from the two edges already present while the global corner pool lets clusters take turns across the full canvas as their local geometry permits.

When an exposed corner wins a turn, growFrom projects three nodes, joins them with five edges, and refreshes the frontier before the next choice, while the renderer gives every stroke a birth time and lets the marks move through green, gold, red, and blue-grey as the pale faces collect beneath them, so the same rule keeps producing a field whose order remains visible even as the drawing expands.

Corner Pool credits kataStatik and Mandra Corners for the degree-two frontier, the outward direction, and the shared global pool that prompted this entry, and K. Moonshot built the isometric geometry, drag seeding, drawing code, and color aging here as an original response to those compositional features.
